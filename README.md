# Сервісний центр «ТехноСервіс» — Вебсистема керування зверненнями з контролем SLA

Вебзастосунок для автоматизації прийому, маршрутизації та моніторингу заявок на ремонт комп’ютерної техніки з регламентним контролем строків виконання (SLA).

**Виконав:** Демешко Микита Ігорович, група АІ-244  
**Дисципліна:** Вебтехнології та вебдизайн (курсовий проєкт, 2026)

---

## Основні можливості системи

- **Трирольова модель доступу (Гість / Клієнт / Менеджер):**
  - **Гість:** перегляд каталогу послуг за категоріями, створення заявки без реєстрації з отриманням унікального трек-номера (`SC-2026-XXXX`), публічне відстеження статусу та історії робіт.
  - **Клієнт:** реєстрація та JWT-автентифікація, автоматична прив’язка заявок до особистого кабінету, перегляд усіх звернень, скасування нової заявки, листування з менеджером.
  - **Менеджер:** KPI-панель контролю SLA (прострочені та заявки на межі дедлайну `< 4 год`), фільтрація й пошук заявок, керування статусами за скінченним автоматом (FSM), коригування дедлайну SLA та вартості, додавання внутрішніх службових приміток (`is_internal`, прихованих від клієнта), керування прайс-листом послуг.
- **Контроль строків SLA:** автоматичний розрахунок дедлайну під час реєстрації звернення на основі нормативного часу послуги та коефіцієнта пріоритету (`urgent ×0.5`, `high ×0.75`, `normal ×1.0`, `low ×1.5`).
- **Стандартизована обробка помилок:** усі помилки REST API повертаються у форматі **RFC 9457 (`application/problem+json`)**.
- **Адаптивний та доступний інтерфейс:** семантична верстка під ширини `360 px`, `768 px`, `1280 px` із підтримкою навігації з клавіатури (WCAG 2.2).

## Технологічний стек

- **Backend:** Python 3.12, FastAPI 0.115.6, SQLAlchemy 2.0.36, Pydantic v2, PyJWT, bcrypt
- **База даних:** PostgreSQL 16 (5 нормалізованих сутностей у 3НФ, індекси, тригер `updated_at`)
- **Frontend:** HTML5, CSS3 (Grid / Flexbox, змінні стилів), Vanilla JavaScript (Fetch API)
- **Інфраструктура та тестування:** Docker, Docker Compose, Pytest, Starlette TestClient

## Запуск проєкту

### Варіант 1. Повний запуск через Docker Compose (рекомендовано)

1. Створіть файл `.env` на основі шаблону:

   ```bash
   cp .env.example .env
   ```

2. Зберіть та запустіть контейнери вебзастосунку та PostgreSQL:

   ```bash
   docker compose up --build -d
   ```

3. Завантажте початкові демонстраційні дані:

   ```bash
   docker compose exec web python -m seed.seed
   ```

4. Відкрийте у браузері:
   - Вебінтерфейс: <http://localhost:8000/>
   - Інтерактивна документація Swagger / OpenAPI: <http://localhost:8000/docs>

### Варіант 2. Локальний запуск у режимі розробки (PyCharm + Docker БД)

1. Підніміть лише контейнер PostgreSQL (порт 5433):

   ```bash
   docker compose up -d db
   ```

2. Активуйте віртуальне середовище та встановіть залежності:

   ```bash
   pip install -r requirements.txt
   ```

3. Заповніть БД тестовими даними та запустіть сервер:

   ```bash
   python -m seed.seed
   uvicorn app.main:app --reload
   ```
